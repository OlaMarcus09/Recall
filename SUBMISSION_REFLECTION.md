# Recall Submission Reflection

## 1. Original Problem and Why It Matters

Recall came from a real study-community pattern: learners ask questions,
answers and explanations are shared, useful course PDFs exist, but the
knowledge becomes hard to recover later. Students then ask the same
questions again or depend on a few active people to find old material.

The problem matters because the community often already has useful
knowledge. The missing layer is memory, trust and retrieval.

## 2. How Codex Was Used

Codex was used as a coding partner across the capstone. The work was
broken into explicit checkpoints from T01 through T10:

- application foundation;
- PDF ingestion with provenance;
- page-scoped KnowledgeUnits;
- semantic retrieval;
- grounded answer and trust states;
- citation validation and learner UI;
- evaluation harness;
- anonymous Community Confusion;
- mobile-first presentation;
- reproducible demo bootstrap.

For each checkpoint, Codex helped inspect the codebase, propose a small
plan, implement scoped changes, add tests, run checks and report the
result.

## 3. What Codex Accelerated

Exact time savings were not measured, so I do not claim a percentage.
Qualitatively, Codex accelerated:

- turning product requirements into implementation tasks;
- writing repetitive but important tests;
- checking provenance and citation edge cases;
- building narrow provider boundaries;
- reviewing diffs for privacy and scope creep;
- producing reproducible demo documentation;
- running repeated pre-publication audits.

The biggest efficiency gain was not just speed of coding. It was the
ability to keep the trust contract visible while moving through many
small slices.

## 4. Quality Improvements From Testing and Review

The project improved because each layer had regression tests before the
next layer was built. Tests cover PDF failures, page provenance,
KnowledgeUnit boundaries, embedding compatibility, stale indexes,
grounded citations, invalid generated citations, refusal behavior,
Community Confusion grouping, web escaping and the demo bootstrap.

Codex also helped catch documentation and safety issues late in the
process, including the need to clarify that Recall stores normalized
question text for anonymous recurring-question grouping while not
storing generated answer records.

## 5. Concrete Challenges Encountered

One challenge was local model/runtime practicality. The project needed a
no-key local retrieval path, so FastEmbed with `BAAI/bge-small-en-v1.5`
was added for embeddings. Local answer-generation runtimes were
investigated but deferred because they were too risky for the demo
machine and deadline.

Another challenge was semantic completeness. Retrieval and citations can
prove grounding, but they do not automatically prove that every part of
a multi-part question was answered. The final MVP is honest about this:
semantic correctness is reviewed separately from machine-checkable trust
properties.

## 6. What the Human Developer Decided

The human developer decided:

- the original problem and first user context;
- that Recall should prioritize refusal over unsupported coverage;
- to use authorized course PDFs as the first material source;
- to keep private BUA material out of the public repository;
- to accept a deterministic extractive provider for the MVP;
- to freeze features before adding WhatsApp or a local LLM;
- to accept the mobile-first visual direction;
- to use synthetic Northstar Bakery material for public reproduction.

Codex supported execution, testing and review, but it did not invent the
product direction.

## 7. Lessons Learned

The strongest lesson was that trust must be designed through the whole
pipeline, not added at the end. Page numbers need to originate at
ingestion. KnowledgeUnits need page-scoped provenance. Retrieval should
be inspectable separately from generation. Generated output should never
own citation metadata.

Another lesson was that evaluation should separate mechanics from
meaning. Automated tests can prove that citations are valid and refusals
work. Human semantic review is still needed to judge whether an answer
fully covers a course concept.

## 8. What Would Be Built With Another Month

With another month, I would focus on:

- calibrated evaluation on more authorized course material;
- a stronger grounded generation provider;
- production authentication and deployment;
- OCR or preprocessing for scanned PDFs;
- better document-management workflows;
- safer retention/deletion controls for learner-question memory;
- improved Community Confusion review tools.

Known limitations remain:

- answers are extractive rather than generated by a tuned local LLM;
- semantic completeness is imperfect;
- the system is English-first;
- PDFs must be text-extractable;
- there is no production authentication or deployment;
- question grouping uses a heuristic threshold that needs calibration.
